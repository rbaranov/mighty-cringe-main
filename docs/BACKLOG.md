   merge. Деплой сам создаст backup и выполнит изолированный restore до установки таймеров. До
   успешного production-прогона пункт не закрыт.

3. **Запись тренировки не теряется и не меняется незаметно.** Синхронизировать старт,
   подходы, завершение и изменения тренировки; сохранить очередь после перезапуска PWA,

   **Статус:** [PR #7](https://github.com/mighty-cringe/mighty-cringe-main/pull/7) влит в `main` и

   проходят; PostgreSQL 17 integration test и production deploy прошли CI. **Требуется участие
   владельца:** проверить на телефоне создание тренировки без сети, восстановление сети и появление
   тренировки после перезагрузки. До этой production-проверки пункт остаётся в бэклоге.

6. **Мои голосовые данные обрабатываются прозрачно и приватно.** Получать явное согласие,
   хранить аудио приватно, обрабатывать через очередь с повторами, показывать статус и
   применять правила удаления.

   **Статус:** реализация готова в
   [stacked draft PR #14](https://github.com/mighty-cringe/mighty-cringe-main/pull/14): перед каждой
   записью требуется версионированное согласие; аудио сначала сохраняется в IndexedDB и переживает
   offline/restart, затем загружается в user-scoped приватное S3-хранилище с SSE-C; PostgreSQL worker
   атомарно забирает задания, повторяет временные сбои и отправляет аудио в OpenRouter с ZDR.
   Интерфейс показывает очередь, обработку, ошибку и расшифровку; playback авторизован, а удаление
   очищает локальную и серверную копии. Ограничения: 60 секунд и 10 MiB. Локальная browser QA
   подтвердила consent gating, очередь, playback UI и встроенное подтверждение удаления без ошибок
   консоли. Docker недоступен локально; контейнерная сборка и PostgreSQL integration test успешно
   прошли в GitHub CI.

   **Требуется участие владельца перед production:** создать отдельный Hetzner project с private
   Helsinki bucket и отдельными S3 credentials; сгенерировать 32-байтный base64 SSE-C key и хранить

   включить ZDR и подтвердить поддержку выбранной STT-моделью нужных форматов; внести все `VOICE_*`
   значения в `/etc/mighty-cringe/production.env`; после merge проверить на телефоне согласие,
   offline-запись, восстановление сети, playback, расшифровку, подтверждение подхода и удаление.

7. **AI не мешает ручной записи.** Сохранить всегда доступный ручной ввод, изолировать ключи
   провайдера от клиента и помечать записи, созданные с помощью AI.

   **Статус:** реализация готова в
   [stacked draft PR #15](https://github.com/mighty-cringe/mighty-cringe-main/pull/15) поверх PR #14.
   Ручной «＋ Подход» остаётся независимым offline-first сценарием; у каждого подхода сохраняется
   неизменяемый источник `manual` / `natural_text` / `voice_ai`, а старые серверные и IndexedDB
   записи мигрируют как ручные. Текущая тренировка и календарная история показывают «AI: голос»
   для cloud-transcription и «текст» для локального детерминированного parser; ручные подходы не
   перегружены меткой. Контракт не позволяет переписать источник при редактировании. CI отдельно
   сканирует PWA source и production bundle и завершится ошибкой, если туда попадёт имя известного
   server-only секрета. Полные локальные tests, typecheck, format, production build, 39 web-тестов,
   PWA shell и secret-boundary проверка проходят; GitHub CI прошёл. **Требуется участие владельца:**
   разрешить последовательный merge PR #12 → #13 → #14 → #15 и проверить метку AI-голоса рядом с
   подтверждённым подходом в production.
