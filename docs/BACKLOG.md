# В РАБОТЕ

1. **Неизвестное упражнение находится и добавляется прямо из команды.**
   **Зачем:** фраза вроде «Замени тягу верхнего блока на тягу Арни» должна не упираться в готовый
   каталог. Приложение само ищет, что имелось в виду, показывает мышцы, оборудование, aliases,
   источники и видео, после подтверждения сохраняет упражнение и завершает исходную команду.
   **Как:** server-side web discovery со структурированным результатом и ссылками на источники;
   один или несколько кандидатов при неоднозначности; user-scoped каталог с offline cache и
   синхронизацией; подтверждение перед сохранением. Первый результат никогда не добавляется молча.
   **Состояние:** реализация готова в ветке `agent/smart-exercise-catalog`: web-grounded discovery,
   карточки кандидатов, подтверждение, user-scoped PostgreSQL/Memory repository, IndexedDB boundary,
   повтор исходной команды, миграция и production preflight. `pnpm test` проходит; локально проверены
   экран каталога и вход в поиск из команды. Для проверки реального результата нужны server-only
   `OPENROUTER_API_KEY` и `EXERCISE_DISCOVERY_MODEL`, затем локальная приёмка владельцем перед merge.
   **Готово, когда:** неизвестное название запускает поиск, владелец выбирает карточку с видео,
   упражнение появляется в его каталоге и команда замены выполняется; после перезапуска и на втором
   устройстве результат сохраняется, чужим пользователям он не виден.

2. **Проект воспроизводимо запускается локально перед каждым merge.**
   **Зачем:** владелец проверяет изменение сам, без production-секретов и ручной починки окружения.
   **Состояние:** реализация готова в ветке `agent/reproducible-local-dev`: `pnpm local:dev`
   автоматически выбирает Docker Compose или native PostgreSQL 16+, поднимает изолированную базу,
   применяет миграции, собирает workspace-пакеты и запускает PWA, API и worker с development-входом.
   Добавлены doctor, status, stop и защищённый reset, а также короткий runbook. Полный `pnpm test`
   прошёл с настоящей PostgreSQL без пропусков; сохранение тренировки после остановки и повторного
   запуска подтверждено. Нужна локальная приёмка владельцем перед merge.
   **Готово, когда:** на чистом checkout владелец проходит runbook, создаёт тренировку и подход,
   перезапускает сервисы, видит сохранённые данные и явно разрешает merge.

# ЖДЁТ ВЛАДЕЛЬЦА

Здесь только проверки, credentials и действия во внешних аккаунтах, которые агент не может
выполнить самостоятельно. Такие пункты не блокируют разработку следующих задач.

1. **Включить и принять поиск неизвестных упражнений.**
   Создать spend-limited OpenRouter key с отключённым input/output logging и ZDR, выбрать актуальную
   модель со strict structured output и web-search plugin, внести `OPENROUTER_API_KEY` и
   `EXERCISE_DISCOVERY_MODEL` сначала в `apps/api/.env`, затем в защищённый production environment.
   Локально проверить «Замени тягу верхнего блока на тягу Арни»: увидеть обоснованные варианты,
   источники и видео, выбрать нужный, выполнить замену; после повторного входа и вторым аккаунтом
   подтвердить сохранение и изоляцию. Инструкция: [ADR 0017](adr/0017-web-grounded-personal-exercise-catalog.md)
   и [production runbook](deployment/hetzner-first-deploy.md).

2. **Принять воспроизводимый локальный контур.**
   На чистом checkout выполнить `corepack enable`, `pnpm install --frozen-lockfile`,
   `pnpm local:doctor` и `pnpm local:dev`. Создать тренировку и подход, остановить процессы через
   `Ctrl+C`, повторно запустить `pnpm local:dev` и убедиться, что данные сохранились. Затем выполнить
   `pnpm test` и явно разрешить merge. Инструкция:
   [локальный runbook](development/local-environment.md).

3. **Принять основной production-сценарий.**

   - [ ] Войти и выйти через Google; двумя аккаунтами подтвердить изоляцию данных.
   - [ ] На установленной PWA без сети восстановить тренировку, изменить план, записать подход
         вручную и текстом, вернуть сеть и дождаться синхронизации.
   - [ ] На своей истории проверить календарь, объём, рабочий вес и расчётный 1RM.
   - [ ] Создать, изменить, удалить и импортировать CSV с замерами тела.
   - [ ] Проверить RU/EN, kg/cm и lb/in после повторного входа и на втором устройстве.

4. **Включить реальные бэкапы и мониторинг.**
   Создать private S3 bucket и отдельные credentials, сохранить `RESTIC_PASSWORD` вне сервера,
   внести backup-группу в production environment и проверить backup → изолированный restore.
   Затем подключить Healthchecks.io, выполнить deploy и проверить аварийное уведомление. Детали:
   [production runbook](../infra/production/README.md), [ADR 0003](adr/0003-encrypted-postgres-backups.md),
   [ADR 0005](adr/0005-production-monitoring.md).

5. **Включить и принять голосовой ввод.**
   Создать отдельный private bucket и S3 credentials для голоса, резервно сохранить SSE-C key,
   создать spend-limited OpenRouter key с отключённым logging и ZDR, внести полную `VOICE_*`-группу
   и выполнить deploy. На телефоне проверить согласие, offline-запись, playback, расшифровку,
   команду, подтверждение, метку «AI: голос» и удаление. Детали:
   [ADR 0011](adr/0011-private-voice-processing.md) и
   [ADR 0012](adr/0012-set-entry-provenance-and-ai-boundary.md).

6. **Принять доступ тренера.**
   Внести email тренера в `TRAINER_EMAILS`, выполнить deploy и двумя аккаунтами проверить
   приглашение → read-only просмотр → отзыв доступа. Детали:
   [ADR 0013](adr/0013-trainer-invites-and-read-only-access.md).

7. **Включить и принять push-напоминания.**
   Создать постоянную VAPID-пару, внести `VAPID_*`-группу, выполнить deploy и на установленной PWA
   проверить opt-in, доставку вне тихих часов и полное отключение. Детали:
   [ADR 0014](adr/0014-opt-in-web-push-delivery.md).
