# Проверка режима подопечного

Сценарий регрессионной проверки режима подопечного, разработанного в `agent/trainee-mode`.
2026-10-08 владелец разрешил merge после подготовки локальной версии.
Архитектура и границы: [ADR 0022](../adr/0022-trainer-journal-context.md).

## Запуск

Основной стек (существующую базу не сбрасывать):

```bash
cd /Users/rb/Sources/mighty-cringe
pnpm local:dev
```

Во втором терминале собрать API и открыть вход в два синтетических аккаунта:

```bash
cd /Users/rb/Sources/mighty-cringe
pnpm --filter @mighty-cringe/api build
pnpm local:trainer-acceptance
```

Если web слушает только `::1`, для второй сессии нужен тот же интерфейс на IPv4:

```bash
pnpm --filter @mighty-cringe/web dev --host 127.0.0.1 --port 5173 --strictPort
```

- [Тестовый тренер](http://localhost:3011/coach) → `http://localhost:5173/`.
- [Тестовый подопечный](http://127.0.0.1:3011/athlete) → `http://127.0.0.1:5173/`.
- [Health](http://127.0.0.1:3000/health).

Разные имена хоста разделяют cookies и IndexedDB. Сервис входа слушает только loopback и использует
фиксированную локальную базу `127.0.0.1:55432/mightycringe_local`; environment URL и production
credentials не используются. Он создаёт только синтетические аккаунты и записи. При повторном запуске
сохраняет их изменения, включая отозванное разрешение. `Ctrl+C` останавливает сервис входа.

## Основной сценарий

1. В окне тренера нажать строку приветствия под логотипом и выбрать «Дмитрий Иванов (тест)».
   Шапка занимает прежнее место: имя подопечного в строке приветствия, «К себе» рядом с логотипом,
   синий акцент. Отдельной полосы под заголовком нет.
2. Открыть текущую тренировку, добавить подход и изменить комментарий. Имя подопечного видно в форме.
   Подход появляется у спортсмена при следующей синхронизации; открытая видимая вкладка обновляется
   каждые 10 секунд. Можно также нажать статус синхронизации → «Синхронизировать сейчас».
3. В «Прогрессе» проверить историю, исходные подходы, графики и замеры. Изменить прошлую тренировку,
   добавить её в избранное, переименовать и убрать из избранного.
4. В каталоге создать личное упражнение, изменить его, добавить в тренировку и удалить из каталога.
   История использовавших его подходов сохраняется. Проверить отметки нравится/не нравится.
5. В настройках журнала и в собственных настройках спортсмена открыть «Изменения тренера»:
   видно действие, имя тренера и время. Аккаунт, согласие на голос и push доступны только владельцу.
6. Нажать «К себе»: вернуться к своему предыдущему разделу и своим тренировкам. Повторно выбрать
   подопечного. После полной перезагрузки приложение начинает с собственного профиля.

## Совместная работа и потеря сети

- Открыть один подход у тренера и спортсмена. Сохранить разные значения сначала у спортсмена,
  затем в оставшейся открытой форме тренера: правка тренера должна дать конфликт, а не молча
  затереть первую запись. Разрешить конфликт в настройках журнала.
- Добавить по новому подходу с двух сторон: обе записи остаются, порядок не дублируется.
- Открыть одно личное упражнение у обоих, изменить у спортсмена, затем сохранить старую форму
  тренера: появляется сообщение об изменении другим участником, введённый текст остаётся в форме.
- Отключить сеть на устройстве тренера, добавить подход: он сохраняется локально; сообщение явно
  называет подопечного и говорит, что запись ещё не передана. «К себе» работает без сети. Новый вход
  в подопечного требует сети и проверки доступа. После её восстановления снова войти в тот же
  журнал: его очередь синхронизируется только с ним.
- У спортсмена: «Настройки → Тренер и доступ → Оставить только просмотр». Очередной запрос тренера
  возвращает его в свой журнал. Новые записи со старым разрешением не принимаются. Повторная выдача
  разрешения создаёт новую версию доступа: старая очередь не проигрывается автоматически.
- Проверить выход из аккаунта с непереданными изменениями в одном из журналов: предупреждение должно
  учитывать и скрытые очереди подопечных. После выхода следующий аккаунт не видит старые локальные данные.

## Мобильная проверка

Ширины 320, 360, 390 и 560 px: шапка не добавляет строку, синхронизация и возврат доступны,
длинное имя сокращается в шапке и читается целиком в переключателе/формах; горизонтальной прокрутки нет.
Проверить форму подхода с клавиатурой, сохранение, отмену и повторное открытие.

Автоматические проверки: `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm format:check`,
`git diff --check`. PostgreSQL integration-тесты запускать только на отдельной тестовой базе.
Результаты выполненных проверок зафиксированы в [DONE](../DONE.md).

## Проверено в этой ветке

- В двух отдельных сессиях подход тренера дошёл до спортсмена; изменение избранного и создание
  личного упражнения записаны в журнал действий.
- Старая открытая форма с 30 кг после сохранения 35 кг у спортсмена дала конфликт; выбор серверной
  версии разрешил его. В сравнении показываются конкретные значения и комментарии.
- На 320/360/390 px проверены шапка, имя и форма подхода; горизонтального переполнения нет.
- Подтверждение отзыва доступа в браузере заблокировала автоматическая проверка разрешений;
  разрешение синтетической связи сохранено для приёмки. Сам отзыв, повторная выдача и запрет
  старого grant покрыты API-тестами на отдельной PostgreSQL.
- `pnpm test`, lint/typecheck, финальная web-сборка и профильные тесты зелёные. Обычный
  `pnpm format:check` сообщает только о локальном игнорируемом `.claude/settings.local.json`.
  Проверка `pnpm exec prettier --check . '!.claude/settings.local.json'` проходит.
