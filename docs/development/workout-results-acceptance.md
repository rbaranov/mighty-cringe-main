# Локальная проверка итога, прогресса и формы подхода

Изменение подготовлено в ветке `agent/workout-results-progress`, после локальной приёмки
владелец разрешил merge 7 октября 2026 года. Ниже сохранён сценарий повторной проверки
из актуального `main` в `/Users/rb/Sources/mighty-cringe`.

## Запуск

Для текущей проверки web работает на <http://localhost:5174>, использует уже запущенный
локальный API на `127.0.0.1:3000` и существующую локальную PostgreSQL. Production-секреты
не нужны. Health через web: <http://localhost:5174/health>.

Повторный запуск frontend при работающем локальном API:

```bash
cd /Users/rb/Sources/mighty-cringe
pnpm build:packages
pnpm --filter @mighty-cringe/web dev --port 5174 --strictPort
```

Для самостоятельного запуска всего стека после остановки других dev-сервисов использовать
обычный `pnpm local:dev` из этой рабочей копии и адрес, напечатанный Vite. Перед запуском
проверить существующий PostgreSQL и порты согласно [local-environment.md](local-environment.md);
не сбрасывать и не перезапускать чужую локальную базу при конфликте портов.

## Сценарий приёмки

1. Начать тестовую тренировку, записать подходы и завершить её. Итог показывает фактически
   выполненные упражнения/подходы, активную длительность и статус сохранения. Упражнения,
   оставшиеся только в плане, не увеличивают число выполненных упражнений.
2. Для упражнения с историей сохранить больше повторов при том же весе. В итоге проверить
   сравнение с последней более ранней тренировкой этого упражнения и исходный подход рекорда.
   Первая запись — точка отсчёта, повтор прежнего результата не объявляется новым рекордом.
3. Перезагрузить страницу на экране итога: он должен восстановиться. Проверить «В избранное»,
   «Открыть тренировку», «Посмотреть прогресс» и возврат к плану.
4. В «Прогрессе» пройти «История / Сила / Замеры», выбрать упражнение и периоды. Нажать точку
   графика, проверить исходные подходы и открыть тренировку. Проверить старые даты, пустой период
   и упражнение с единственной тренировкой. Замеры, календарь и редактирование истории доступны.
5. В новом и существующем подходе проверить `−` / `+`, автозаполненные значения, комментарий,
   голосовой/текстовый переход, подсказку RIR и сохранение. На телефоне отдельно проверить
   экранную клавиатуру, прокрутку шторки и доступность сохранения на коротком экране.
6. В установленной PWA повторить сохранение и завершение без сети, затем вернуть сеть:
   итог и аналитика видны по локальным данным, статус синхронизации обновляется.

В локальном demo-аккаунте для проверки создан синтетический подход с комментарием
«Синтетический подход для проверки итога и графика». Это не production-данные.

## Выполненные проверки

Полный `pnpm test`, финальный web-прогон из 245 тестов после обновления до #74, typecheck, lint, production build,
форматирование, PWA offline-shell и проверка границы секретов прошли. Три PostgreSQL
integration-теста штатно пропущены без отдельной тестовой БД.

В браузере проверены завершение и перезагрузка итога, график и исходные подходы, выбор периодов,
переходы в историю/замеры и ручной ввод. Форма проверена на 320×640, 360×800, 390×844 и 390×510
без горизонтального переполнения; увеличенные кнопки имеют области нажатия минимум 44×44 px.
На синтетическом подходе подтверждено сохранение дробного веса при изменении только повторов
и применение явной правки веса. Это не заменяет проверку клавиатуры на телефоне и offline-запуска
установленной PWA владельцем.

Первичная локальная приёмка завершена; сценарий можно повторять при последующих изменениях.
